SchemaOutputBenchmark for 3.2.0: one generator for each column and thread, reseeded for each value.

This is not a full dashboard run: only SchemaOutputBenchmark ran, on one machine, with the publication
protocol of METHODOLOGY.md, in two sittings one after the other. The first compares origin/main with the
change, in the order main, change, change, main; the second compares the change with e6ba573d, the last
commit before 3.0.1, in the order e6ba573d, change, change, e6ba573d. Each run had the machine to itself
through a lock that kept every other heavy job off it, and each ran in its own exported source tree. Each
operation generates or writes 250 records of twelve Field references, seeded with 7. The benchmark's
largeSchemaBatch calls generateBatch at e6ba573d and nextRecords, which returns the same records, later.

Environment: Temurin 21.0.13+9, Darwin 27.2.0 arm64, Apple M5 Pro, JMH 1.37
Command: ./gradlew :benchmarks:jmh -PjmhArgs="SchemaOutputBenchmark -foe true -wi 3 -i 5 -f 3 -t 1 -prof gc"
